CHANGELOGの自動更新などでCodex CLIをCIに組み込むと、だいたいこう書きますよね。

```yaml
- name: Update changelog via Codex
  run: |
    npm install -g @openai/codex
    codex login --api-key "${{ secrets.OPENAI_KEY }}"
    codex exec --full-auto "update CHANGELOG for next release"

```

ところが、`codex login`は内部的にPythonに依存しており、CI環境によってはうまく動かないことがあります。さらに最近の変更で「環境変数によるAPIキー認証」が効かず、認証情報は `~/.codex/auth.json` に統一された挙動になっている模様。結果として、世にあるサンプルのCIがまとめてコケやすい状況に…

参考: https://github.com/openai/codex/pull/3189

---

## 認証仕様の整理

- `codex login`自体は「常時必須」ではない
    - ChatGPTプラン利用時: `codex login`（引数なし）でブラウザ認証
    - OpenAI APIキー利用時: `codex login --api-key "your-api-key"`
    - 既に認証済み: `~/.codex/auth.json` があれば再ログイン不要
- 初回は何らかの方法で認証が必要で、以後は `auth.json` が使われる
- 環境変数にAPIキーを入れるだけでは認証されない挙動のため、CIは `auth.json` 前提で考えるのが安全

---

## CIで起きがちな問題

- `codex login` のPython依存で失敗
- ブラウザ認証（引数なしlogin）はCIでは不可能
- 毎回クリーンなランナーだと `auth.json` がなく、都度ログインが必要

---

## こけないための実践パターン

### 1) v33.0までを使う

```yaml
- name: Install Codex
  run: npm install -g @openai/codex@v33.0
- name: Update changelog via Codex
  run: codex exec --full-auto "update CHANGELOG for next release"

```

---

### 2) `auth.json` をシークレット配布してログインをスキップ（Python依存回避）

ローカルで一度認証して得た `~/.codex/auth.json` をシークレットへ保存し、CIで書き戻します。

```yaml
- name: Restore Codex auth.json
  run: |
    mkdir -p ~/.codex
    cat > ~/.codex/auth.json <<'JSON'
    ${{ secrets.CODEX_AUTH_JSON }}
    JSON
    chmod 600 ~/.codex/auth.json
- name: Install Codex
  run: npm install -g @openai/codex
- name: Update changelog via Codex
  run: codex exec --full-auto "update CHANGELOG for next release"

```

注意

- `auth.json` は機密。コミット禁止。必ずシークレットで渡す
- 扱いにくければbase64化して保存→CIでデコードでもOK

---

### 3) `~/.codex` ディレクトリをキャッシュ（再ログイン抑制）

```yaml
- uses: actions/cache@v4
  id: cache
  with:
    path: ~/.codex
    key: ${{ runner.os }}-codex-auth
- name: Install Codex
  run: npm install -g @openai/codex
- name: Ensure login if cache miss
  if: steps.cache.outputs.cache-hit != 'true'
  run: codex login --api-key "${{ secrets.OPENAI_KEY }}"
- name: Update changelog via Codex
  run: codex exec --full-auto "update CHANGELOG for next release"

```

注意

- キャッシュはブランチやOSごとに分かれる
- 資格情報をキャッシュに含めるリスクを理解のうえで採用

---

### 4) 実行環境を固定（事故減らし）

Python入りの固定ベース（例: ubuntu-latest + setup-python、またはPython同梱のNodeコンテナ）を使い、毎回同じ前提で動かす。

---

## まとめ

- 仕様変更により、環境変数だけでのAPIキー認証は期待どおりに動かず、`~/.codex/auth.json` 依存が強まった
- CIでは「ブラウザ認証不可」「Python依存あり」を前提に、以下で安定化
    - Pythonを入れてAPIキーで `codex login`
    - `auth.json` をシークレット配布してloginをスキップ
    - `~/.codex` をキャッシュ
    - 実行環境を固定
- 既存のサンプルワークフローはコケやすいので早めに見直しを
参考: https://github.com/openai/codex/pull/3189

このあたりを押さえておけば、CHANGELOGの自動更新なども引き続き安定して回せます。
